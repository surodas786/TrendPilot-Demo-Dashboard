# 14 Nov 2026 — XAU_USDT Live trailing take profit rejected with MEXC 2001

**Window:** 21:27–21:28 Asia/Dhaka (15:27–15:28 UTC). **Contract:** XAU_USDT. **Exit:** Trailing
Take Profit, CLOSE SHORT 12 contracts. **Result:** every attempt filled 0/12 and was rejected with
`MEXC_2001`, each with a different `externalOid`.

## What is established from the code

* **The loop (confirmed).** A trailing level that has been crossed reports `triggered` on every
  later price (`advanceTrailing` does not change state when it triggers). Before this fix,
  `processPaperClose` marked a rejected close `REJECTED` and released the one-unresolved-close
  scope; the next `market.tick` called `requestExit` again, which created a **new intent with a
  new random client order ID**. So each price produced a new order with a new `externalOid`. Take
  profit targets behaved the same (the target was released back to `PENDING`).
* **The payload follows the documented mapping.** MEXC place-order (read 2026-11-14): `side` 2 =
  close short, 4 = close long; `openType` 1 isolated, 2 cross; `positionMode` 1 hedge, 2 one-way
  (default hedge); `reduceOnly` "only applicable in one-way mode". The incident-time code sent
  `side: 2, type: 5, vol, positionId, externalOid` (32 hex characters) plus
  `reduceOnly: true, positionMode: 2` for a connection stored as One-way. The side value is the
  documented one.
* **What else could differ.** The incident-time request took two fields from TrendPilot instead of
  from MEXC:
  * `openType` came from TrendPilot's stored margin mode, not from the MEXC position's `openType`.
  * `positionMode` and `reduceOnly` came from the mode stored when the connection was verified,
    not from the account's current `position_mode` (the opening path re-reads it; the close path
    did not).
  If MEXC holds the Short as **cross** while TrendPilot sent `openType: 1`, or the account is in
  **Hedge** mode while the request said `positionMode: 2` with `reduceOnly`, MEXC has no matching
  position for that direction. That is consistent with "order direction error" (2001), but MEXC
  does not document it. `ops:close-incident-trace` prints both values and the field-by-field
  difference; if none differ, the cause is outside the mapping, and MEXC support is asked
  (below) before anything about the side is changed.
* **Running revision.** The worker heartbeat did not record a revision before this release. From
  this release on, it reports `revision` (the `GIT_SHA` env var, or `git rev-parse HEAD`) in
  `service_heartbeats.detail`, and the worker logs it at start.

## What changed

1. One close serializer, `buildMexcCloseOrder` (`packages/db/src/live/mexcVenue.ts`). It serves
   every close: manual, fixed/split TP, trailing TP, signal close, reversal and emergency close,
   Long and Short, in both modes. It matches the exchange position (by the stored MEXC
   `positionId` when known, never a newer one) and caps the volume at what that position holds.
   It uses that position's `openType`, the account mode read from MEXC right before sending,
   `reduceOnly` in one-way mode, and the stored 32-character `externalOid`. The side mapping is
   unchanged.
2. Every submission stores sanitized evidence on the intent (`venue_request`: endpoint and body;
   `venue_response`: code and message). Credentials and signatures are never stored.
3. A deterministic rejection (2001, 2002/2022, 600, 2011, 2015, 2027, 2029, 2030, auth, an
   unverified capability, a position mismatch) halts automatic exits for the position
   (`positions.exit_halted_at` / `exit_halt_reason`). Other rejections of the same trigger are
   spaced at least 30 s apart, and automatic exits halt after 3 of them. A manual close is always
   accepted. The halt is shown to the investor, and the exchange stop is untouched. Migration
   0026 backfills the halt for open Live positions that already have a deterministic rejection,
   so the deploy does not replay the old exit.
4. Ambiguous responses (timeout, network, 5xx) behave as before: the order is looked up by its
   `externalOid` and is not resent before the grace period. A reversal still opens only after
   MEXC reports the old position flat and its stop gone.
